직접 만든 해시 테이블 위의 키-값 저장소

명령

해시 테이블 내부

칸 개수 - 저장 개수 - 로드 팩터 - (1 이상이면 칸 2배)

ht[0]

ht[1] (새 테이블)

· 같은 칸에 여러 키가 있으면 충돌 → 리스트로 이어서 저장(체이닝)
· TTL이 끝난 키는 0.1초 안에 자동으로 사라짐(Active 삭제). 그 사이에 GET 해도 바로 지워짐(Lazy 삭제)
· 키 수가 칸 수만큼 차면 2배 테이블(ht[1])을 만들고, 명령이 올 때마다 ht[0]의 칸을 하나씩 옮김(점진적 rehash)
· 노란 칸 = 다음에 옮길 칸

동시성 실험: 카운터 올리기

같은 키를 동시에 N번 +1 했을 때 결과가 N인지 확인해요.
· GET + PUT: 값을 읽고(GET) → +1 해서 → 저장(PUT). 두 명령 사이에 다른 요청이 끼어들 수 있음
· INCR: 읽기·더하기·저장을 서버가 락 안에서 한 번에 처리
